## Reproduce

Use Node 22 or newer for development tooling; the packaged extension targets Node 20 and has been exercised in VS Code 1.90.

```sh
npm ci
npm run check
npm run package
npm run verify:package
npm run test:opencode
VSCODE_TEST_VERSION=1.90.0 JUPYTER_TEST_VERSION=2024.5.0 npm run test:host
VSCODE_TEST_VERSION=1.143.1 npm run test:host
```

`test:host` needs a desktop display on Linux; CI uses `xvfb-run`. VS Code 1.90 initially passed on the desktop display, but a later rerun crashed in its old Electron GPU process on this Fedora 44 system. The final rerun, including the execution-race fixes, passed on an isolated Xvfb display. Xvfb was extracted under `/tmp` without a system installation. Development F5/watch now rebuilds the bundled entry point and emits source maps; release builds omit them. `compile` separately checks types and emits modules used by the focused tests.

## 0.2.1 saved-cell execution correction

The first actual notebook execution attempt exposed a gap in the original controller fixture: saved notebooks restore `executionOrder` without `success`. The 0.2.0 guard incorrectly classified that metadata as an active prior execution and rejected the request before contacting either Colab or a local kernel. The exact error was reproduced in a failing test before the fix.

0.2.1 removes that inference while retaining fresh execution correlation and cancellation/timeout protections. All 22 focused tests pass. The current/minimum host workflows also pass with an explicitly restored historical count, and the 0.2.1 VSIX passes the isolated bundle/package verification. It is installed in AI and the default profile. Actual selected-kernel verification remains pending the user's window reload; these host passes are not presented as Colab/Python-kernel validation. See T010.
