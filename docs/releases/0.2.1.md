Published 2026-10-26 to the [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=KrisspyWang.opencode-jupyter) using `vsce publish --packagePath`. The version initially remained **Verifying** after upload, so the public catalog continued to list 0.1.3. Follow-up publisher inspection confirmed that 0.2.1 passed Marketplace validation (Validated flag set). Upload success and a downloadable VSIX alone were not sufficient evidence of completed validation. Publication was explicitly requested by the user; the manual validation gaps below remain unverified. This release includes the unpublished 0.2.0 development work and its saved-cell execution fix. The previous public version was 0.1.3.

## Release notes

OpenCode v2 can connect directly to the extension's Streamable HTTP `/mcp` endpoint. Generated configuration now uses the v2 schema, and the README explains startup order, reconnecting an existing daemon, and Remote-WSL/SSH host placement. Legacy SSE remains available for migration during 0.2.x.

Three new tools—`jupyter_list_cells`, `jupyter_read_cell_input`, and `jupyter_read_cell_output`—let agents inspect individual cells without fetching the whole notebook. Cell IDs survive source edits and insertion above the cell while the notebook remains open. Output handling preserves MIME types, encodes binary data as base64, supports complete MCP images, and reports truncation.

Notebook edits preserve metadata and historical outputs. Execution waits for fresh events and reports timeout/cancellation explicitly. A correction in 0.2.1 allows cells with saved execution counts and no `success` field to run; the earlier development build incorrectly rejected them before dispatching to either a local or Colab kernel.

The server now isolates client sessions, binds to loopback, validates Host/Origin, bounds requests and session resources, and handles start/stop and occupied ports reliably. Runtime dependencies are bundled. VS Code's declared minimum remains 1.90.0.

Kernel status uses a public Jupyter API when available and otherwise reports unknown. Variable inspection and programmatic kernel restart return explicit unsupported errors. Cell-to-prompt integration (#1) remains deferred.

## Upgrade and reconnect

1. Install the VSIX into the profile used by the notebook window. For the affected local profile:

   ```sh
   code --profile AI --install-extension artifacts/opencode-jupyter-0.2.1.vsix --force
   ```

2. Run **Developer: Reload Window**, open the notebook, and run **OpenCode Jupyter: Show MCP Configuration**. Merge its OpenCode v2 configuration into the existing project configuration:

   ```json
   {
     "mcp": {
       "servers": {
         "jupyter-vscode": {
           "type": "remote",
           "url": "http://127.0.0.1:9123/mcp",
           "oauth": false,
           "protocol": "legacy"
         }
       }
     }
   }
   ```

   Here `legacy` selects the initialization-era MCP protocol over Streamable HTTP. It does not select the `/sse` transport. Use the generated port if it differs from 9123. OpenCode and the extension must reach the same workspace host.

3. From the notebook project directory, reconnect a daemon that cached the old endpoint:

   ```sh
   opencode api experimental.mcp.connect --param server=jupyter-vscode --param "location[directory]=$PWD"
   opencode mcp list
   ```
